# Offline AI Knowledge Store

## Decision

The reusable offline AI knowledge-store template belongs in `open-education-suite` because it is platform infrastructure. Subject repos own their own public-safe seed manifests and records. A separate repository is not needed yet; split it out only if the store becomes a standalone service with its own release cycle, UI, sync daemon, or non-education consumers.

This keeps the three layers complementary:

- `open-education-suite` owns the schema, local build tool, runtime adapter contract, learner-state boundary, and shared retrieval/write rules.
- Subject repos own course-specific AI knowledge seeds, provenance, allowed record types, and public/private boundaries.
- Local AI runtimes such as Ollama and LM Studio consume the same store package through provider profiles.

## What Exists Now

The suite already has AI teacher prompt and evaluation contracts, but it did not have an offline database template. This store fills that gap. It packages course-owned seed records into deterministic local artifacts:

- `manifest.json` for store metadata and runtime profiles.
- `records.jsonl` for portable retrieval records.
- `offline-knowledge-store.sqlite` for local read/write access by tools and local AIs.

No network access or credentials are required to build the store.

## Storage Model

The baseline store is intentionally simple and offline-first.

| Layer | Purpose | Mutability |
| --- | --- | --- |
| Course seed manifest | Public-safe course-owned source map. | Versioned in the content repo. |
| Course seed records | Public-safe retrieval metadata and summaries. | Versioned in the content repo. |
| JSONL package | Portable local exchange format for local AI tools. | Generated by suite tooling. |
| SQLite package | Local database for lookup, notes, and sync log. | Generated locally; not committed. |
| Private overlays | Learner notes, AI notes, embeddings, preferences, and experiments. | Local/private only. |

## Provider Profiles

Provider profiles are model-runtime adapters, not durable truth.

| Profile | Runtime | Default Endpoint | Notes |
| --- | --- | --- | --- |
| `ollama-local` | Ollama | `http://127.0.0.1:11434` | Preferred default. Uses local chat and embedding endpoints when installed. |
| `lm-studio-local` | LM Studio | `http://127.0.0.1:1234/v1` | OpenAI-compatible local fallback. Useful when LM Studio hosts the chosen model. |

The suite should let the owner pick model names at runtime. Store manifests name provider profiles but should not hard-code private model inventory.

## Required Boundaries

- Do not commit private learner data, embeddings derived from private notes, chat logs, recordings, credentials, API keys, or local absolute paths.
- Do not copy copyrighted source text into course seed records unless the content repo source-packet rules explicitly allow it.
- AI-generated notes are proposals or overlays until checked code promotes public-safe content back into a content repo.
- Local AIs may read seed records and private overlays, but durable learner state still changes only through checked suite state-update code.
- Every answer that uses course content must cite `sourceRepo` and `sourcePath`.

## Subject Repo Manifest

Each subject repo can expose one manifest path from `content-repo.json`:

```json
{
  "aiKnowledgeStore": {
    "manifestPath": "ai-knowledge/manifest.json",
    "recordsPath": "ai-knowledge/records.jsonl",
    "status": "seed-ready"
  }
}
```

The manifest describes the course-owned seed. The suite builder reads it through `content-sources.json`, validates records, and emits a local package.

## Runtime Use

Local AI calls should follow this order:

1. Read deterministic learner state and next action.
2. Retrieve course seed records from the offline store.
3. Read private overlays only from user-approved local storage.
4. Build a grounded prompt with citations.
5. Invoke the selected runtime profile, usually Ollama first and LM Studio as fallback.
6. Evaluate model output before proposing state changes.
7. Write notes or proposed updates only to local overlays unless promotion is explicitly approved.

## Build Command

```powershell
.\scripts\ai\build-offline-knowledge-store.ps1 -Provider ollama -OutputRoot .\.codex-cache\tmp\offline-ai-store
```

Use `-Provider lm-studio` to select the LM Studio profile. Use `-Check` to validate manifests and records without writing the package.
